### Question clarity and repairs during checks (build 46)

Inspection questions use darker text and a compact four-choice layout: Fault, Can't complete, I fixed it, and OK. SI/SOP citations appear beneath the question in smaller text. They link to the source PDF only when one published document in the current organisation has the matching document reference and an attached source; missing or ambiguous matches remain plain text. Original instructions and limits remain stored. A duplicate Full instruction panel is hidden; questions explicitly requiring acknowledgement still require it, using an inline acknowledgement when the question already contains the full instruction.

I fixed it requires the original fault, the repair, the successful recheck and confirmation. Required measurements must be entered again and must pass their limits. Failed readings already recorded are retained with the repair and recheck. The saved result is Fixed (repair reported), with a linked fault and work awaiting supervisor review. It never closes a fault or releases the bus. Existing assigned corrective work is preserved. Repair details are visible in inspection history, fault/action reviews, the bus timeline and fault CSV/garage exports.

Visual faults prompt for up to three photos, including repairs made during a check. Organisation/Platform Admins can enable Require a photo for visual faults on each PM3 question. It defaults to optional until enabled. The setting applies to new inspections; saved inspections keep their original setting. The server enforces mandatory photos using authorised uploaded attachments. The tolerance exception requires recorded failed measurements, so a client cannot omit a required photo merely by labelling a visual defect a tolerance failure. Existing fault photos remain attached.
